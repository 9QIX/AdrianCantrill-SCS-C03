## What the Demonstration Proves

## Detection, Logging, and Evidence

Use AWS CloudTrail for control-plane changes to AWS CloudFormation. For packet-path questions, enable VPC Flow Logs on the relevant interfaces, subnets, or VPC; flow logs show accepted or rejected IP flows but do not capture packet payloads. Combine service status and metrics with route-table, DNS, policy, and firewall configuration evidence.

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| Connection times out | Missing route, return path, or filtering rule | Inspect effective routes, security groups, network ACLs, and Flow Logs | Restore symmetric routing and least-privilege traffic rules |
| Access is denied | Identity, resource, endpoint, key, or organization guardrail denies the request | Inspect CloudTrail error context and all applicable policies | Add the required allow or remove the unintended explicit deny |
| Expected private path is unused | DNS or a more-specific route selects another destination | Resolve the hostname and compare the route table with destination addresses | Correct private DNS, endpoint associations, or routes |
| Works in one Availability Zone only | Zonal resource, association, or return path is missing | Compare endpoint/gateway placement and route tables per AZ | Deploy and associate the required zonal components |

## Security Best Practices

- Apply least privilege to management and data-plane access for AWS CloudFormation, Amazon EC2, AWS Site-to-Site VPN.
- Prefer private paths and managed controls when they meet the requirement, but validate both routing and authorization.
- Design across Availability Zones where the service is zonal and the workload requires resilience.
- Log configuration changes and network behavior; alert on unauthorized or high-risk changes.
- Test an explicit denial path so an unnoticed public or uninspected fallback is not mistaken for success.

## Common Exam Traps

- Do not assume that creating AWS CloudFormation automatically updates routes, policies, DNS, or filters unless the service explicitly performs that integration.
- Network reachability is not IAM authorization, and an IAM allow cannot repair a missing route.
- Logging observes activity; it does not automatically prevent or remediate it.
- Regional, Availability Zone, and global scope matter. Place dependencies in the scope required by the service.
- Explicit deny overrides an applicable allow; default behavior is implicit deny where IAM authorization applies.

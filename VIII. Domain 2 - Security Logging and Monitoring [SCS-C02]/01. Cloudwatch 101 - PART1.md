# Amazon CloudWatch Fundamentals: Metrics and Namespaces

## Overview

Amazon CloudWatch collects monitoring data for AWS resources, applications, and hybrid environments. This first part focuses on metrics: time-ordered numeric data used for visibility, alarms, and automation. Metrics indicate behavior; they are not API audit records.

## Exam Alignment

- **Primary SCS-C03 Domain:** Detection
- **Secondary Domain(s):** Incident Response
- **Main AWS Services:** Amazon CloudWatch, Amazon EC2
- **Lesson Type:** Concept
- **Exam Importance:** High
- **Core Skill:** Interpret CloudWatch metric identity, resolution, retention, and scope for detection.

## Core Concepts

- A metric is uniquely identified by its namespace, metric name, and complete dimension set.
- AWS namespaces typically use `AWS/<Service>`; custom namespaces must be supplied when publishing custom metrics.
- Dimensions are name/value pairs that create distinct time series. High-cardinality dimensions can multiply cost and operational complexity.
- Each data point has a timestamp and optional unit. CloudWatch aggregates data with statistics such as average, minimum, maximum, sum, sample count, and percentiles.
- Metrics are Regional. They cannot be manually deleted and expire after 15 months without new data.
- Standard-resolution custom metrics use 60-second granularity; high-resolution custom metrics can use one-second granularity and support shorter alarm periods at additional cost.

## How It Works

```text
AWS service / agent / application
        -> namespace + metric + dimensions
        -> timestamped data points
        -> statistics, dashboards, alarms, automation
```

## Detection, Logging, and Evidence

Metrics are efficient for thresholds and trends but normally lack the event detail required for forensics. Correlate a metric anomaly with CloudWatch Logs, CloudTrail, VPC Flow Logs, or application traces to identify cause and actor.

## Common Exam Traps

- Amazon EC2 publishes CPU metrics, but guest memory and disk-use metrics normally require the CloudWatch agent or custom publication.
- A metric's dimensions are part of its identity, not display-only tags.
- Aggregated metrics are not a substitute for raw logs.
- Cross-account dashboards do not make the underlying metrics globally scoped.

## Memory Hooks

> **Metrics tell how much and when; logs tell what happened in detail.**

## Quick Review

- Namespace, name, and dimensions identify a metric.
- Metrics are Regional.
- Choose statistics and periods that match the signal.
- Watch cardinality and cost.
- Correlate anomalies with detailed evidence.

## Self-Check Questions

1. Why do two data points with different dimension values belong to different metrics?

<details><summary>Answer</summary>

Because the complete dimension set is part of a CloudWatch metric's unique identity.

# Amazon CloudWatch Logs Architecture

## Overview

Amazon CloudWatch Logs ingests, stores, queries, filters, and routes log events from AWS services, applications, and systems. Security design must address log-group scope, retention, encryption, permissions, data protection, and downstream delivery.

## Exam Alignment

- **Primary SCS-C03 Domain:** Detection
- **Secondary Domain(s):** Incident Response
- **Main AWS Services:** CloudWatch Logs, AWS KMS, Amazon Data Firehose, AWS Lambda
- **Lesson Type:** Architecture
- **Exam Importance:** High
- **Core Skill:** Design protected log ingestion, analysis, retention, and streaming paths.

## Core Concepts

- A log group defines retention, encryption, class, access, and other shared settings; log streams group events from a source.
- Standard log class supports the broad feature set, including subscription and metric filters. Infrequent Access lowers ingestion cost but supports a reduced feature set. Delivery class is specialized for Lambda log delivery to S3 or Firehose and has fixed two-day retention.
- Logs Insights performs interactive queries; metric filters transform matching log events into CloudWatch metrics.
- Subscription filters stream matching events in near real time to supported destinations. They are not the same as metric filters.
- Resource policies and service roles allow supported AWS services to deliver logs.

## Detection, Logging, and Evidence

Apply explicit retention, least-privilege read access, and AWS KMS encryption when customer control is required. Use cross-account observability or destination policies for centralized operations. Protect sensitive fields with data-protection policies and avoid secrets in logs at the source.

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| No events arrive | Source/agent or delivery permission failed | Check agent status and resource policy | Correct configuration and permission |
| Metric never changes | Filter pattern or dimensions wrong | Test pattern against sample events | Correct filter and metric definition |
| Subscription silent | Unsupported log class or destination policy issue | Inspect class and delivery errors | Use Standard class or correct destination access |

## Common Exam Traps

- CloudWatch Logs stores and analyzes logs; CloudTrail generates AWS API event records.
- Metric filters create numeric metrics; subscription filters forward log events.
- Indefinite retention is not automatic; configure the required retention period.
- Encryption does not grant readers access to use the KMS key.

## Memory Hooks

> **Log group governs, stream organizes, Insights queries, metric filter counts, subscription filter forwards.**

## Quick Review

- Choose log class from required features.
- Set retention and encryption deliberately.
- Restrict ingestion and read permissions.
- Separate metric and subscription filters.
- Centralize evidence without exposing sensitive content.

## Self-Check Questions

1. Which filter sends matching log events to a downstream processor?

<details><summary>Answer</summary>

A subscription filter. A metric filter emits numeric metric data instead.

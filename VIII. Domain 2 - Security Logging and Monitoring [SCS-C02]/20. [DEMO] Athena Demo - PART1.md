# Demonstration: Querying OpenStreetMap Data with Athena — Part 1

## Overview

This part configures Athena to query the public Planet OpenStreetMap dataset in Amazon S3. It demonstrates serverless schema-on-read analysis without building a database or modifying source data.

## Exam Alignment

- **Primary SCS-C03 Domain:** Incident Response
- **Secondary Domain(s):** Detection
- **Main AWS Services:** Amazon Athena, Amazon S3, AWS Glue Data Catalog
- **Lesson Type:** Demonstration
- **Exam Importance:** Medium
- **Core Skill:** Configure a controlled Athena workgroup/result location and validate an external dataset schema.

## Demonstration Goal

Prepare the query environment and catalog metadata required to locate veterinary facilities in Part 2.

## Prerequisites

- An account/Region with Athena access.
- Permission to create catalog databases/tables and a workgroup or use an approved one.
- A private S3 query-results location with encryption and lifecycle settings.
- Read access to the public dataset used by the lab.

## Demonstration Steps

1. Select the intended Region and create or choose a restricted Athena workgroup.
2. Configure a unique private S3 results prefix and enforce encryption.
3. Create the lesson database and external table definitions for the OpenStreetMap dataset.
4. Verify each table's S3 location, serialization format, columns, and complex data types.
5. Run a small, selective query with a limit to validate schema and permissions.
6. Inspect bytes scanned and the result object written to S3.

## Validation

- Catalog database and tables appear in the selected Region.
- A limited query returns expected columns without changing the source dataset.
- Query history and CloudTrail identify the caller.
- Results are written only to the approved encrypted prefix.

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| Output location error | Workgroup/result bucket not configured | Inspect workgroup settings | Configure writable S3 results prefix |
| Access denied | Missing S3, Glue, or KMS permission | Review query error and CloudTrail | Correct least-privilege access |
| Invalid rows | Schema/SerDe does not match objects | Inspect table definition and sample format | Correct metadata rather than source data |

## Cleanup

Retain the catalog objects for Part 2. After completing both parts, remove lab result objects and catalog definitions only if they have no continuing use.

## What the Demonstration Proves

Athena can immediately query existing S3 data by applying cataloged structure at read time; secure query output and authorization remain the customer's responsibility.

## Quick Review

- Configure results before querying.
- Use a workgroup for governance.
- External tables do not copy source data.
- Validate with small selective queries.
- Track bytes scanned and secure results.

# Amazon Inspector Vulnerability Management

## Overview

Amazon Inspector is a vulnerability-management service that continually discovers and scans supported Amazon EC2 instances, Amazon ECR container images, and AWS Lambda functions. It produces prioritized findings for software vulnerabilities and unintended network exposure.

## Exam Alignment

- **Primary SCS-C03 Domain:** Detection
- **Secondary Domain(s):** Incident Response
- **Main AWS Services:** Amazon Inspector, Amazon EC2, Amazon ECR, AWS Lambda, AWS Systems Manager, AWS Security Hub
- **Lesson Type:** Architecture
- **Exam Importance:** High
- **Core Skill:** Select Inspector for continuous workload vulnerability assessment and route findings for remediation.

## Core Concepts

- EC2 scanning finds package vulnerabilities and network reachability issues; inventory can use AWS Systems Manager agent-based scanning or Amazon EBS snapshot-based agentless scanning where supported.
- ECR enhanced scanning uses Inspector for continuous image vulnerability evaluation according to configured scope and rescan duration.
- Lambda standard scanning checks package dependencies; optional Lambda code scanning analyzes custom code for supported runtimes and requires standard scanning.
- Inspector findings include affected resource, vulnerability details, severity, exploitability context, and remediation information.
- Delegated administration supports organization-scale management; Security Hub can aggregate findings.

## Exam Decision Guide

| Requirement | Service | Why |
| --- | --- | --- |
| Find CVEs in EC2/ECR/Lambda | Amazon Inspector | Managed vulnerability scanning |
| Detect anomalous API or network behavior | Amazon GuardDuty | Threat detection from supported telemetry |
| Find sensitive data in S3 | Amazon Macie | Data discovery and S3 posture |
| Aggregate findings | AWS Security Hub | Central finding normalization and posture view |

## Common Exam Traps

- Current Inspector is continuous vulnerability management, not the older template/run assessment-agent model.
- Inspector detects vulnerabilities; it does not patch every workload automatically.
- Coverage depends on supported resources, runtimes, scan configuration, and permissions.
- A vulnerable package finding is not proof of exploitation.

## Memory Hooks

> **Inspector finds workload vulnerabilities; GuardDuty finds suspicious behavior; Macie finds sensitive S3 data.**

## Quick Review

- Know EC2, ECR, and Lambda scan types.
- Track coverage as well as findings.
- Prioritize by severity and exploitability context.
- Route findings centrally.
- Remediation requires a separate patch/deployment workflow.

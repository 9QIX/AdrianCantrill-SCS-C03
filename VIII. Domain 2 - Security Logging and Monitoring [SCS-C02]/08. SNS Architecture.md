# Amazon SNS Publish/Subscribe Architecture

## Overview

Amazon Simple Notification Service (Amazon SNS) is a managed publish/subscribe service. Publishers send a message to a topic, and SNS fans it out to subscribed endpoints such as Amazon SQS, Lambda, HTTP/S, email, SMS, or mobile push.

## Exam Alignment

- **Primary SCS-C03 Domain:** Incident Response
- **Secondary Domain(s):** Detection
- **Main AWS Services:** Amazon SNS, Amazon SQS, AWS Lambda, Amazon CloudWatch
- **Lesson Type:** Architecture
- **Exam Importance:** Medium
- **Core Skill:** Design secure, filtered, resilient fan-out for alerts and events.

## Core Concepts

- Standard topics prioritize scale and support broad endpoint types with at-least-once delivery and possible duplicates/order variation.
- FIFO topics support ordered, deduplicated delivery to compatible endpoints such as SQS FIFO queues.
- Subscription filter policies reduce messages delivered to each subscriber.
- Topic resource policies control publishers and cross-account subscribers; endpoint policies may also be required.
- Server-side encryption with AWS KMS protects stored message data, subject to key-policy authorization.

## Architecture and Service Relationships

```text
Detector/publisher -> SNS topic -> email notification
                              |-> SQS queue -> durable worker
                              `-> Lambda -> automated response
```

## Common Exam Traps

- SNS is push fan-out; SQS is durable pull-based queuing.
- Email delivery is appropriate for people, not reliable machine remediation.
- Topic access does not automatically grant a subscriber access to downstream resources.
- Encryption does not replace topic and key policies.

## Memory Hooks

> **SNS fans out; SQS buffers; Lambda acts.**

## Quick Review

- Use one topic for multiple independent subscribers.
- Add SQS for durable buffering.
- Filter subscriptions to reduce noise.
- Scope topic and endpoint policies.
- Monitor delivery failures and DLQs where supported.

## Self-Check Questions

1. Why place SQS between SNS and a response worker?

<details><summary>Answer</summary>

It buffers bursts and provides durable decoupling so the worker can retry and process at its own rate.

</details>

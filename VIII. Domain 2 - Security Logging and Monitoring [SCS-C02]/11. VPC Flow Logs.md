# Amazon VPC Flow Logs

## Overview

Amazon VPC Flow Logs record metadata about IP traffic to and from network interfaces. They can be enabled for a VPC, subnet, or elastic network interface and delivered to CloudWatch Logs, Amazon S3, or Amazon Data Firehose. They do not capture packet payloads.

## Exam Alignment

- **Primary SCS-C03 Domain:** Detection
- **Secondary Domain(s):** Incident Response, Infrastructure Security
- **Main AWS Services:** Amazon VPC, CloudWatch Logs, Amazon S3, Amazon Data Firehose
- **Lesson Type:** Architecture / Troubleshooting
- **Exam Importance:** High
- **Core Skill:** Use flow metadata to investigate allowed/rejected network paths and select scalable log delivery.

## Core Concepts

- Records aggregate flows by interface and network tuple over a capture window; one-minute or ten-minute maximum intervals are available, with Nitro interfaces using one minute or less.
- Choose accepted, rejected, or all traffic.
- Default format contains version-2 fields; custom format can add richer metadata.
- Delivery is best effort and delayed, not a real-time packet stream.
- `ACCEPT` or `REJECT` reflects evaluated network controls but does not identify application payload or final application success.

## Detection, Logging, and Evidence

Useful fields include source/destination addresses and ports, protocol, packets, bytes, timestamps, action, log status, interface, and optional service metadata. Query high-volume S3/Parquet logs with Athena; use CloudWatch Logs for near-term search, metric filters, and alarms.

## Common Exam Traps

- Flow Logs do not capture payload, DNS query content, or every excluded traffic type.
- A rejected flow cannot alone identify whether a security group, network ACL, or other path control caused it.
- Logging at VPC scope covers interfaces in scope, not traffic outside supported capture behavior.
- Delivery delay and best-effort metadata matter in investigations.

## Memory Hooks

> **Flow Logs show who talked to whom, when, and whether the flow was accepted—not what they said.**

## Quick Review

- Enable at VPC, subnet, or interface scope.
- Choose accept/reject/all and a useful custom format.
- Select CloudWatch, S3, or Firehose by analysis path.
- Expect delay and best-effort delivery.
- Correlate with DNS, load balancer, firewall, and application logs.

## Self-Check Questions

1. Can Flow Logs prove which HTTP path a client requested?

<details><summary>Answer</summary>

No. They contain network-flow metadata, not Layer 7 request payloads.

</details>

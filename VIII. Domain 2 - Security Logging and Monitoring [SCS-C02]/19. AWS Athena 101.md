# Amazon Athena for Security Log Analysis

## Overview

Amazon Athena is a serverless interactive query service that uses SQL to analyze data in Amazon S3 without loading it into a database. Security teams use it for ad hoc investigation of CloudTrail, VPC Flow Logs, load balancer, and application logs.

## Exam Alignment

- **Primary SCS-C03 Domain:** Incident Response
- **Secondary Domain(s):** Detection
- **Main AWS Services:** Amazon Athena, Amazon S3, AWS Glue Data Catalog, AWS Lake Formation
- **Lesson Type:** Architecture
- **Exam Importance:** High
- **Core Skill:** Query protected S3 evidence efficiently with schema-on-read and least-privilege workgroups.

## Core Concepts

- Athena SQL reads source data in place using table metadata, commonly stored in the AWS Glue Data Catalog.
- Schema-on-read interprets bytes during query; it does not transform the original evidence.
- Query cost is primarily based on data scanned. Columnar formats, compression, partitions, and selective predicates reduce scan cost.
- Workgroups isolate teams, enforce settings, publish metrics, and control query-result locations and limits.
- Athena must be authorized to read source objects/catalog metadata, decrypt KMS-encrypted data, and write encrypted query results.

## Architecture and Service Relationships

```text
Protected S3 logs + Glue catalog schema -> Athena workgroup/query
                                      -> encrypted S3 results
```

## Exam Decision Guide

| Requirement | Service | Why |
| --- | --- | --- |
| Ad hoc SQL over logs already in S3 | Athena | Serverless schema-on-read querying |
| Persistently catalog file schemas | Glue Data Catalog | Central metadata store |
| Fine-grained data-lake authorization | AWS Lake Formation | Governs cataloged data access |
| Managed CloudTrail event query store | CloudTrail Lake | Purpose-built event data stores and SQL |

## Common Exam Traps

- Athena does not ingest or copy source data merely to query it.
- A table definition contains metadata, not the underlying rows.
- Query results can contain sensitive evidence and need encryption, retention, and access control.
- `SELECT *` increases scan cost and data exposure.

## Memory Hooks

> **S3 holds bytes, Glue describes them, Athena queries them, Lake Formation governs access.**

## Quick Review

- Use Athena for ad hoc S3 log investigation.
- Partition by common time/account/Region filters.
- Prefer Parquet/ORC and compression where appropriate.
- Secure workgroups and result buckets.
- Keep original evidence unchanged.

## Self-Check Questions

1. Does creating an Athena external table move CloudTrail logs into Athena?

<details><summary>Answer</summary>

No. The table defines schema and location; Athena reads the S3 objects in place.

</details>

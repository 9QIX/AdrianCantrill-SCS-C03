# Amazon CloudWatch Fundamentals: Alarms, Dashboards, and Actions

## Overview

This second part turns CloudWatch measurements into operational detection. Alarms evaluate metric or metric-math results and transition among `OK`, `ALARM`, and `INSUFFICIENT_DATA`; configured actions can notify or invoke supported automation.

## Exam Alignment

- **Primary SCS-C03 Domain:** Detection
- **Secondary Domain(s):** Incident Response
- **Main AWS Services:** Amazon CloudWatch, Amazon Simple Notification Service (Amazon SNS), Amazon EventBridge, AWS Systems Manager
- **Lesson Type:** Architecture
- **Exam Importance:** High
- **Core Skill:** Configure alarm evaluation and route state changes to reliable response workflows.

## Core Concepts

- Period controls data aggregation; evaluation periods and datapoints-to-alarm control how many recent periods must breach.
- Missing-data treatment can be `breaching`, `notBreaching`, `ignore`, or `missing`; select based on whether silence is failure.
- Composite alarms combine other alarms to reduce noise and model multi-signal conditions.
- Dashboards visualize state but do not alert by themselves.
- Alarm actions occur on state transitions and can target SNS, Auto Scaling, Systems Manager, and other supported actions.
- EventBridge can match alarm state-change events and route them to broader workflows.

## How It Works

```text
Metric -> statistic and period -> threshold evaluation -> alarm state change
                                               -> SNS / EventBridge / automation
```

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| `INSUFFICIENT_DATA` | Missing/delayed points or period mismatch | Inspect metric timestamps and resolution | Correct publication, period, or missing-data behavior |
| Alarm flaps | Threshold too close to normal variance | Compare history and evaluation settings | Adjust threshold or require more breaching periods |
| Alarm changes but no response | Target permission or subscription issue | Inspect alarm history and target delivery | Correct policy, role, endpoint, or subscription |

## Common Exam Traps

- An alarm is stateful; it does not repeatedly invoke an action merely because it remains in one state.
- `INSUFFICIENT_DATA` does not automatically mean healthy or unhealthy.
- Monitoring and notification do not equal remediation.
- CloudWatch alarm evidence does not identify the API caller; use CloudTrail for that.

## Memory Hooks

> **Measure, evaluate, transition, route, respond.**

## Quick Review

- Tune period, threshold, and datapoints-to-alarm together.
- Choose missing-data handling deliberately.
- Use composite alarms to reduce noise.
- Validate target permissions and subscriptions.
- Correlate alarms with detailed logs.

## Self-Check Questions

1. What does `INSUFFICIENT_DATA` mean?

<details><summary>Answer</summary>

The alarm lacks enough evaluated data to determine `OK` or `ALARM`; the security meaning depends on the monitored signal.

</details>

# Amazon EventBridge Event Routing

## Overview

Amazon EventBridge is the current event-routing service that evolved from CloudWatch Events. Event buses receive events; rules match event patterns and send matching events to targets. EventBridge Scheduler is the preferred dedicated capability for large-scale scheduled tasks.

## Exam Alignment

- **Primary SCS-C03 Domain:** Incident Response
- **Secondary Domain(s):** Detection
- **Main AWS Services:** Amazon EventBridge, AWS Lambda, Amazon SNS, Amazon SQS, AWS Systems Manager
- **Lesson Type:** Architecture
- **Exam Importance:** High
- **Core Skill:** Route security events reliably to notification, containment, or orchestration targets.

## How It Works

```text
AWS/custom/SaaS event -> event bus -> rule pattern -> target
                                              |-> DLQ/retry handling
```

- The default event bus receives supported AWS service events; custom and partner buses support application and SaaS sources.
- Event patterns filter event fields. Scheduled rules use rate or cron expressions; EventBridge Scheduler adds dedicated scheduling features.
- Targets include Lambda, SNS, SQS, Step Functions, Systems Manager, other event buses, and API destinations.
- EventBridge requires permission to invoke targets, through execution roles or target resource policies depending on target type.
- Delivery is asynchronous; design consumers to be idempotent and configure retries and dead-letter queues where supported.

## Detection, Logging, and Evidence

EventBridge usually routes a detection generated elsewhere. Monitor rule metrics, failed invocations, DLQs, and target logs. Archive/replay can support recovery for eligible event buses when configured before the need arises.

## Common Exam Traps

- EventBridge routes events; it does not itself detect every threat.
- CloudWatch Events is the older name and capability subset; use EventBridge terminology.
- A matching rule cannot invoke a target without the appropriate permission model.
- A scheduled rule's time zone behavior differs from EventBridge Scheduler capabilities; verify scheduling requirements.

## Memory Hooks

> **Detector emits; EventBridge matches and routes; target responds.**

## Quick Review

- Build precise event patterns.
- Use resource policies or roles as required by the target.
- Make handlers idempotent.
- Monitor failures and DLQs.
- Prefer EventBridge Scheduler for advanced scheduling.

## Self-Check Questions

1. Which service should route a GuardDuty finding to a Step Functions response workflow?

<details><summary>Answer</summary>

# Demonstration: Querying OpenStreetMap Data with Athena — Part 2

## Overview

This part queries a geographic bounding box to find veterinary facilities. The technique illustrates targeted predicates, nested data handling, and cost-aware serverless analysis that also apply to incident evidence in S3.

## Exam Alignment

- **Primary SCS-C03 Domain:** Incident Response
- **Secondary Domain(s):** Detection
- **Main AWS Services:** Amazon Athena, Amazon S3, AWS Glue Data Catalog
- **Lesson Type:** Demonstration
- **Exam Importance:** Medium
- **Core Skill:** Run scoped SQL investigations and validate results while minimizing scanned data.

## Demonstration Goal

Return relevant OpenStreetMap veterinary locations inside a chosen latitude/longitude rectangle.

## Prerequisites

- Part 1 workgroup, result bucket, database, and table.
- Decimal latitude/longitude boundaries for the chosen area.
- Understanding that north/east values increase and south/west values decrease in signed decimal degrees.

## Demonstration Steps

1. Use a map tool to record north, south, east, and west decimal boundaries.
2. Select only needed columns from the OpenStreetMap table.
3. Filter latitude between south and north and longitude between west and east.
4. Filter tags or attributes for veterinary/animal-care facilities according to the lab schema.
5. Limit exploratory results, then refine names and coordinates.
6. Review bytes scanned, query duration, and encrypted result output.

## Validation

- Returned coordinates lie inside the defined rectangle.
- Results contain expected veterinary feature metadata.
- Repeated execution is read-only against source data.
- Query output is stored in the governed results prefix.

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| No results | Coordinates reversed or tag filter too narrow | Test boundary and tag predicates separately | Correct signed decimal bounds/filter |
| Excessive scan cost | No partition/column pruning or broad query | Review bytes scanned | Select columns and constrain partitions/predicates |
| Duplicate-looking locations | Source data contains multiple feature types/versions | Inspect IDs and feature metadata | Deduplicate only with justified query logic |

## Cleanup

Delete the lab-only database/table definitions and query-result objects after confirming they are not shared. The public source dataset is not owned by the learner and must not be altered.

## What the Demonstration Proves

Athena supports rapid ad hoc investigation of large external datasets. Query scope, schema correctness, result protection, and cost controls are part of the security design.

## Memory Hooks

> **Define the evidence window, select only needed fields, filter early, and protect the results.**

## Quick Review

- Use signed decimal coordinates correctly.
- Decompose complex filters during troubleshooting.
- Avoid `SELECT *` for large evidence sets.
- Review bytes scanned.
- Treat result files as potentially sensitive.

## Self-Check Questions

1. Why should query results receive separate security controls?

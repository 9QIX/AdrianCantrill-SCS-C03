# CloudTrail Log File Integrity Validation

## Overview

CloudTrail log file integrity validation detects modification or deletion of delivered trail log files. CloudTrail hashes each log file and delivers hourly digest files that contain log hashes, the previous digest signature, and an RSA digital signature.

## Exam Alignment

- **Primary SCS-C03 Domain:** Incident Response
- **Secondary Domain(s):** Detection
- **Main AWS Services:** AWS CloudTrail, Amazon S3, AWS Key Management Service (AWS KMS)
- **Lesson Type:** Architecture / Troubleshooting
- **Exam Importance:** High
- **Core Skill:** Validate the provenance and continuity of CloudTrail evidence for forensic use.

## How It Works

```text
CloudTrail log -> SHA-256 hash -> hourly digest
previous digest signature ------^       |
CloudTrail RSA private key -> digest signature
investigator -> public key + digest chain + log hashes -> validation result
```

CloudTrail uses a different key pair per Region. Digest files are stored separately in the same bucket as trail logs. Enabling validation starts digest delivery; it does not automatically execute validation.

## Configuration or Workflow

1. Enable log file validation on the trail before the incident period.
2. Protect the S3 log and digest prefixes with least privilege, versioning, retention controls, and separation of duties.
3. Validate the required Region and time range from the original S3 delivery location.

```bash
aws cloudtrail validate-logs \
  --trail-arn <TRAIL_ARN> \
  --start-time <ISO_8601_UTC> \
  --end-time <ISO_8601_UTC> \
  --region <AWS_REGION>
```

### Line-by-Line Comments

```text
Line 1: Starts CloudTrail digest and log validation.
Line 2: Identifies the trail whose digest chain is authoritative.
Lines 3-4: Bounds the evidence interval in UTC.
Line 5: Selects the Region-specific validation chain.
```

### Code Walkthrough

This read-only validation requires S3 list/read and bucket-location access. For an organization trail, specify the account ID when validating a particular member account. The AWS CLI expects files in their original delivery location; use a custom validator for moved/offline evidence.

## Common Exam Traps

- SSE-KMS encryption provides confidentiality; digest validation provides tamper evidence.
- Validation cannot retroactively cover periods when digest delivery was disabled.
- A valid digest chain does not prove the recorded action was authorized or benign.
- Moving files can prevent AWS CLI validation even if a custom validation workflow remains possible.

## Memory Hooks

> **Logs are hashed, digests are chained and signed, validation reveals change or deletion.**

## Quick Review

- Enable validation before evidence is needed.
- Digest files arrive about hourly.
- SHA-256 hashes protect logs; RSA signatures protect digests.
- Validate per Region and original location.
- Protect both logs and digests.

## Self-Check Questions

1. Does enabling log validation immediately verify all existing logs?

<details><summary>Answer</summary>

No. It starts digest delivery for subsequent covered logs; validation is a separate operation.

</details>

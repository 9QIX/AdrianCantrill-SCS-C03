# IAM Access Keys and Programmatic Credentials

## Overview

An IAM access key consists of an access key ID and a secret access key used to sign AWS API requests. It is a long-term credential until deactivated or deleted. Prefer temporary AWS STS credentials delivered through roles, federation, or workload-native credential providers.

## Exam Alignment

- **Primary SCS-C03 Domain:** Identity and Access Management
- **Secondary Domain(s):** Detection
- **Main AWS Services:** IAM, AWS STS, AWS CloudTrail
- **Lesson Type:** Concept
- **Exam Importance:** High
- **Core Skill:** Reduce, protect, rotate, detect, and replace long-term programmatic credentials.

## Core Concepts

- The secret access key is displayed only when created; losing it requires creating a replacement.
- A key authenticates as its owning IAM user. It does not contain permissions; policies determine authorization.
- Applications on AWS should normally use service roles rather than keys embedded in code or configuration.
- Human CLI users should prefer federated or IAM Identity Center sessions and temporary credentials.
- Up to two access keys can facilitate rotation, but both active keys remain usable.

## How It Works

```text
Access key ID + secret -> SigV4 request signature -> AWS authentication
                                            -> IAM authorization -> API result
```

## Detection, Logging, and Evidence

CloudTrail records supported API activity and identifies the access key ID used. Credential reports and last-used information support review, but usage metadata has documented scope and reporting latency. Never place secret keys in logs.

## Security Best Practices

- Do not create root access keys.
- Prefer temporary credentials and automated credential providers.
- Store unavoidable secrets in a protected secret store, not source code.
- Rotate by creating and testing a replacement before deactivating and later deleting the old key.
- Investigate exposed keys, deactivate them promptly, preserve evidence, and review CloudTrail activity.

## Common Exam Traps

- Access keys are not the same as SSH key pairs.
- MFA on console authentication does not automatically add MFA to access-key calls.
- Deactivation is reversible; deletion is not.
- Rotation without updating every consumer can cause outages.

## Memory Hooks

### One-Line Memory Hook

> **Keys identify; policies authorize; roles avoid long-lived keys.**

## Quick Review

- Treat secret access keys as high-value secrets.
- Prefer STS temporary credentials.
- Never embed keys in code or images.
- Use CloudTrail to investigate key activity.
- Rotate, validate, deactivate, then delete.
- A key itself grants no permissions.

## Self-Check Questions

1. What is the preferred credential source for an EC2 workload?

<details><summary>Answer</summary>

An IAM role attached through an instance profile, which supplies temporary credentials.

</details>

2. What should happen first when a key is confirmed exposed?

<details><summary>Answer</summary>

Contain the risk by deactivating or otherwise revoking it, then investigate activity, replace dependencies, and delete it when safe.

</details>

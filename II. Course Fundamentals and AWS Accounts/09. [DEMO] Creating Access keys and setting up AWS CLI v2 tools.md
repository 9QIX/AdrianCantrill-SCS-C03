# Configuring AWS CLI v2 Credentials Safely

## Overview

This demonstration configures AWS Command Line Interface (AWS CLI) v2 access and validates caller identity. The legacy lab path uses an IAM-user access key; current production practice prefers IAM Identity Center, role assumption, or workload roles with temporary credentials.

## Exam Alignment

- **Primary SCS-C03 Domain:** Identity and Access Management
- **Secondary Domain(s):** Detection
- **Main AWS Services:** IAM, AWS STS, IAM Identity Center, AWS CloudTrail
- **Lesson Type:** Demonstration
- **Exam Importance:** High
- **Core Skill:** Configure a named CLI profile, verify the active principal, and avoid exposing long-term credentials.

## Demonstration Goal

Install AWS CLI v2, establish an authorized credential source, and verify the identity and account used by commands.

## Prerequisites

- AWS CLI v2 from an official distribution.
- An approved IAM Identity Center assignment, role workflow, or—only for this legacy lab—an IAM-user access key.
- A selected default Region and output format.

## Demonstration Steps

1. Install AWS CLI v2 and confirm the executable version.
2. Prefer `aws configure sso` to create a named IAM Identity Center profile. If the lab specifically requires a key, create it for the intended IAM user and capture the secret once.
3. Configure a named profile rather than silently replacing an unrelated default profile.
4. Store local AWS configuration and credential files with operating-system access restricted to the user.
5. Verify the caller before any modifying command.

```bash
aws --version
aws sts get-caller-identity --profile <PROFILE_NAME>
```

### Line-by-Line Comments

```text
Line 1: Displays the installed AWS CLI version.
Line 2: Returns the account, principal ARN, and user ID for the named profile.
```

### Code Walkthrough

The first command is local and read-only. The STS call is also read-only and normally requires no explicit identity permission, though organization or endpoint controls can still prevent access. Verify the returned account and ARN before changing resources.

## Validation

- `aws --version` reports AWS CLI v2.
- `get-caller-identity` returns the expected account ID and principal ARN.
- No secret is printed, committed, pasted into shell history, or stored in the repository.
- A test read-only service command uses the intended Region and profile.

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| `Unable to locate credentials` | Profile missing or not selected | Inspect profile names and credential provider chain | Select or configure the intended profile |
| `InvalidClientTokenId` | Invalid, deleted, or mismatched credential | Verify source and profile without displaying secrets | Refresh temporary credentials or replace the key |
| Wrong account returned | Wrong profile or environment variable precedence | Run `get-caller-identity` and inspect provider settings | Remove unintended overrides and select the right profile |
| Request expired/signature error | Local time or signing inputs wrong | Check clock and Region | Synchronize time and correct configuration |

## Cleanup

If a long-term key was created only for the exercise, first confirm it has no remaining dependency, then deactivate and delete it through the authorized IAM workflow. Do not remove credentials still used by an application.

## What the Demonstration Proves

CLI authentication is separate from authorization, and profile verification prevents changes in the wrong account. Temporary credentials reduce the lifetime and handling burden of secrets.

## Common Exam Traps

- `aws configure` does not validate that a key belongs to the intended account.
- A default Region does not restrict which Regions a principal may use.
- Successful `get-caller-identity` does not prove permission to call other services.
- Environment variables can override profile-file credentials.

## Quick Review

- Prefer SSO or role-based temporary credentials.
- Use named profiles.
- Verify account and ARN before changes.
- Keep secrets out of repositories and logs.
- Understand credential-provider precedence.
- Remove lab-only long-term keys safely.

## Self-Check Questions

1. Which command verifies the current CLI principal?

<details><summary>Answer</summary>

`aws sts get-caller-identity`, ideally with the explicit named profile.

</details>

2. Does setting a CLI Region prevent calls to other Regions?

<details><summary>Answer</summary>

No. It supplies a default endpoint selection; authorization and governance controls must impose Region restrictions.

</details>

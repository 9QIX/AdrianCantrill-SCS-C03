# Adding MFA to the AWS Account Root User

## Overview

This demonstration protects root-user console authentication with a second factor. Because root has account-wide authority and performs sensitive account tasks, root MFA is an initial account-security requirement.

## Exam Alignment

- **Primary SCS-C03 Domain:** Identity and Access Management
- **Secondary Domain(s):** Security Foundations and Governance
- **Main AWS Services:** AWS account management, IAM
- **Lesson Type:** Demonstration
- **Exam Importance:** High
- **Core Skill:** Register and validate MFA for the AWS account root user.

## Demonstration Goal

Require the root user's password and registered MFA factor for interactive sign-in.

## Prerequisites

- Authorized access to the root email and password.
- A supported MFA device or authenticator.
- A protected recovery process and accurate account contacts.

## Demonstration Steps

1. Sign in as the root user and open **Security credentials**.
2. Choose **Assign MFA device**, select the supported device type, and provide a descriptive device name.
3. For an authenticator application, scan the displayed QR code without sharing or storing it insecurely.
4. Enter the requested consecutive one-time codes and complete registration.
5. Sign out, then sign in again with the root email, password, and current MFA response.
6. End routine root use and switch to the approved federated or administrative role workflow.

## Validation

- Root sign-in requests the registered MFA factor.
- A current code succeeds; an invalid or expired code fails.
- The root security-credentials page shows the expected MFA device.
- CloudTrail and alerting can identify subsequent root activity where applicable.

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| Consecutive codes rejected | Device clock drift or incorrect seed | Check device time and selected account entry | Synchronize time or repeat authorized enrollment |
| Device lost | Recovery path required | Confirm access to root email/phone and account details | Follow the official root MFA recovery process |
| MFA succeeds but action is denied | Authorization or guardrail issue | Review policies and CloudTrail | Correct the applicable policy; MFA is not an allow |

## What the Demonstration Proves

Compromise of the root password alone is no longer sufficient for interactive root sign-in. It does not eliminate risks from insecure recovery channels, existing root access keys, or authorized but dangerous root actions.

## Memory Hooks

### One-Line Memory Hook

> **Root: lock it with MFA, watch it, and rarely use it.**

## Quick Review

- Root MFA is an initial account control.
- Protect both the MFA device and recovery channels.
- Validate enrollment by signing out and back in.
- Avoid root access keys.
- Use governed non-root administration for daily work.

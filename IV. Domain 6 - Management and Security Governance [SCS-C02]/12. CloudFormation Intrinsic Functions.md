# CloudFormation Intrinsic Functions

## Overview

CloudFormation intrinsic functions calculate values, reference resources, import shared values, and conditionally construct templates. They keep infrastructure definitions portable but can obscure privilege and dependency relationships if overused.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** AWS CloudFormation
- **Lesson Type:** Concept
- **Exam Importance:** Medium
- **Core Skill:** Select intrinsic functions and understand the dependencies and security-sensitive values they create.

## Core Concepts

| Function | Purpose | Key Point |
| --- | --- | --- |
| `Ref` | Returns a parameter value or resource-specific identifier | Return value depends on resource type |
| `Fn::GetAtt` | Returns a resource attribute | Often used for ARNs or generated endpoints |
| `Fn::Sub` | Substitutes variables in strings | Useful for readable ARN construction |
| `Fn::Join` | Joins values with a delimiter | Less readable than `Sub` for many strings |
| `Fn::FindInMap` | Retrieves a mapping value | Static template lookup |
| `Fn::ImportValue` | Imports another stack's exported output | Creates a cross-stack dependency |
| `Fn::If` | Selects values based on a condition | Can return `AWS::NoValue` |
| `Fn::Select` / `Fn::Split` | Extracts from or divides lists/strings | Invalid indices or assumptions cause failures |

## Security Implications

- Inspect the fully resolved ARN, policy resource, principal, and condition value—not only the shorthand expression.
- Dynamic construction can accidentally broaden a policy if account, Region, partition, or wildcard placement is wrong.
- Intrinsic references usually create dependency ordering; hard-coded strings do not.
- Do not use functions to embed secrets in outputs or metadata.

## Common Exam Traps

- `Ref` does not always return an ARN.
- `GetAtt` attributes vary by resource type.
- `ImportValue` cannot import arbitrary runtime data and constrains exporter changes while imported.
- Intrinsic functions do not execute arbitrary code.

## Memory Hooks

> **Ref identifies, GetAtt extracts, Sub builds, FindInMap looks up, ImportValue crosses stacks.**

## Quick Review

- Know the common functions by purpose.
- Verify the resolved security-sensitive value.
- Prefer readable expressions.
- Understand implicit dependencies.
- Avoid exposing secrets.

## Self-Check Questions

1. Which function normally retrieves a resource's ARN attribute?

<details><summary>Answer</summary>

`Fn::GetAtt`, using the attribute supported by that resource type.

</details>

2. When is `Fn::Sub` preferred over manual string assembly?

<details>
<summary>Answer</summary>

Use `Fn::Sub` to construct strings with parameter, resource, or pseudo-parameter values clearly. `Fn::Join` remains useful when joining a list with a delimiter.

</details>

3. Can an intrinsic function call an arbitrary external API?

<details>
<summary>Answer</summary>

No. Intrinsic functions evaluate template values within CloudFormation. Use a custom resource when provisioning requires supported external logic.

</details>

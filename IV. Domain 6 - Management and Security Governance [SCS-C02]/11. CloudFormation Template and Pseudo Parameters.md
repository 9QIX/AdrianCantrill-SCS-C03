# CloudFormation Templates and Pseudo Parameters

## Overview

A CloudFormation template declares infrastructure using standard sections. Pseudo parameters expose deployment context—such as account, Region, partition, stack name, and stack ID—without requiring users to enter those values.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** AWS CloudFormation
- **Lesson Type:** Concept
- **Exam Importance:** Medium
- **Core Skill:** Build portable, least-privilege templates without hard-coded environmental identifiers.

## Core Concepts

- `Resources` is the only required template section.
- Common optional sections include parameters, mappings, conditions, outputs, metadata, rules, and transforms.
- Parameters accept operator input; pseudo parameters are supplied by CloudFormation.
- Common pseudo parameters include `AWS::AccountId`, `AWS::Region`, `AWS::Partition`, `AWS::StackName`, `AWS::StackId`, `AWS::URLSuffix`, `AWS::NotificationARNs`, and `AWS::NoValue`.
- Use `AWS::Partition` instead of hard-coding `aws` when ARNs must work across partitions.

## Security Implications

- Marking a parameter `NoEcho` masks it in common displays but does not make the template a secure secret store.
- Prefer dynamic references or purpose-built secret services for sensitive values.
- Validate allowed values and patterns to reduce misconfiguration.
- Do not expose secrets through outputs, metadata, identifiers, or logs.

## Common Exam Traps

- Pseudo parameters are not user-supplied template parameters.
- `NoEcho` does not protect values placed in every resource property, output, or metadata location.
- Account and Region portability requires more than replacing a single hard-coded ARN.

## Memory Hooks

> **Parameters come from the operator; pseudo parameters come from CloudFormation context.**

## Quick Review

- `Resources` is required.
- Use pseudo parameters for deployment context.
- Use `AWS::Partition` for portable ARN construction.
- Do not store plaintext secrets in templates.
- Constrain input parameters where possible.

## Self-Check Questions

1. Which pseudo parameter helps make an ARN partition-portable?

<details><summary>Answer</summary>

`AWS::Partition`.

</details>

2. What is the security risk of accepting an unconstrained parameter?

<details>
<summary>Answer</summary>

A parameter can select an unapproved network, image, key, or resource size. Use allowed values, patterns, types, rules, and higher-level governance where appropriate.

</details>

3. Why are pseudo parameters preferable to hard-coded account or Region values?

<details>
<summary>Answer</summary>

Pseudo parameters make templates portable and reduce accidental deployment with stale identifiers, but they do not themselves grant permissions.

</details>

# AWS Trusted Advisor

## Overview

AWS Trusted Advisor evaluates AWS environments against AWS best-practice checks across categories such as cost optimization, performance, security, fault tolerance, service limits, and operational excellence. Check availability and refresh behavior can depend on the account's support plan and organizational configuration.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Detection
- **Main AWS Services:** AWS Trusted Advisor, AWS Support, AWS Organizations, Amazon EventBridge
- **Lesson Type:** Concept
- **Exam Importance:** Medium
- **Core Skill:** Use Trusted Advisor recommendations appropriately and distinguish advisory checks from enforcement.

## Core Concepts

- Trusted Advisor produces check results and recommendations; it does not automatically enforce most changes.
- Results may identify exposed resources, weak security configuration, quota pressure, resilience risks, or waste.
- Organizational views can centralize eligible results across accounts when prerequisites are met.
- Event-driven integrations can route supported status changes, but remediation requires a separate authorized workflow.
- AWS Health communicates events affecting AWS services or resources; Trusted Advisor evaluates best-practice posture.

## Exam Decision Guide

| Requirement | Service | Why |
| --- | --- | --- |
| Best-practice recommendations | Trusted Advisor | Evaluates supported checks and recommends improvements |
| Historical resource configuration compliance | AWS Config | Records and evaluates configuration state |
| AWS service/account operational events | AWS Health | Communicates relevant events and planned changes |
| Enforce maximum member-account permissions | SCP | Preventive organization policy |

## Common Exam Traps

- A green check is not a complete security assessment.
- Recommendations do not equal prevention or remediation.
- Not every check is available under every support plan.
- Quota recommendations do not themselves request increases.

## Memory Hooks

> **Trusted Advisor recommends; Config evaluates state; SCP prevents; automation responds.**

## Quick Review

- Review check scope and freshness.
- Treat findings as recommendations requiring ownership.
- Verify support-plan eligibility.
- Use organization views where supported.
- Add explicit workflows for alerting and remediation.

## Self-Check Questions

1. Does Trusted Advisor block a risky configuration?

<details><summary>Answer</summary>

No. It reports supported best-practice check results; prevention or remediation requires other controls.

</details>

2. Does AWS Trusted Advisor enforce its recommendations?

<details>
<summary>Answer</summary>

No. Trusted Advisor provides checks and recommendations; remediation must be performed manually or through a separate automation workflow.

</details>

3. What should be considered before acting on a recommendation?

<details>
<summary>Answer</summary>

Validate the check's scope, support-plan availability, refresh time, exclusions, business impact, and current resource state. A recommendation is evidence for a decision, not an automatic change.

</details>

# CloudFormation Conditions

## Overview

CloudFormation conditions evaluate parameters, pseudo parameters, mappings, or other conditions to control whether resources or outputs are created and which property values are used. They enable one template to support controlled environment differences.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** AWS CloudFormation
- **Lesson Type:** Concept
- **Exam Importance:** Medium
- **Core Skill:** Apply conditions without accidentally omitting security controls or creating unsafe environment variance.

## Core Concepts

- Define named conditions in the `Conditions` section.
- Associate a condition with resources or outputs, or use `Fn::If` in supported property values.
- Functions include `Fn::Equals`, `Fn::And`, `Fn::Or`, `Fn::Not`, and `Fn::If`.
- `AWS::NoValue` removes a property when returned from `Fn::If`.
- Conditions are evaluated during create and update operations; they are not general runtime logic.

## Security Implications

- A production condition might enable stronger logging, retention, or protection, but baseline security should not disappear accidentally in non-production.
- Validate every branch: an untested false branch can deploy public, unencrypted, or unmonitored resources.
- A condition cannot be used as an authorization policy.

## Common Exam Traps

- Conditions do not continuously monitor resource state.
- A condition normally depends on inputs and other conditions, not directly on resource attributes.
- Conditional deletion of a resource during update can cause data loss unless retention is designed.

## Memory Hooks

> **Conditions decide what the stack declares; policies decide who may act.**

## Quick Review

- Conditions are evaluated at stack operations.
- Use `Fn::If` for conditional property values.
- `AWS::NoValue` removes a property.
- Test every environment branch.
- Do not confuse conditions with IAM authorization.

## Self-Check Questions

1. Can a CloudFormation condition deny an API request after deployment?

<details><summary>Answer</summary>

No. It controls template evaluation; IAM and resource policies govern API authorization.

</details>

2. Do CloudFormation conditions prevent unauthorized API calls?

<details>
<summary>Answer</summary>

No. Conditions decide whether template resources or properties are created. IAM, resource policies, SCPs, and other controls still authorize the resulting API calls.

</details>

3. When is `AWS::NoValue` useful?

<details>
<summary>Answer</summary>

Return it from `Fn::If` to remove an optional property rather than supplying an invalid empty value.

</details>

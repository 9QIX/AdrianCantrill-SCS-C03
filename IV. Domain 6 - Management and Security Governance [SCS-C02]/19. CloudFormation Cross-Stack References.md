# CloudFormation Cross-Stack References

## Overview

Cross-stack references let one CloudFormation stack export a value and another stack import it. This supports independently managed layers such as networking and applications, while creating an explicit lifecycle dependency.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** AWS CloudFormation
- **Lesson Type:** Architecture
- **Exam Importance:** Supporting
- **Core Skill:** Share non-sensitive values between stacks and manage the resulting coupling.

## How It Works

```text
Producer stack Output + Export name -> Region/account export registry
                                      -> Consumer Fn::ImportValue
```

Exports and imports must be in the same account and Region. Export names must be unique there. CloudFormation prevents deletion or incompatible modification of an export while it is imported.

## Security Implications

- Export resource identifiers, not secrets.
- Protect foundational producer stacks from unauthorized updates or deletion.
- Evaluate whether consumers receive an ARN/ID only or actual authorization; importing a value grants no permissions.
- Plan versioned migrations when a shared value must change.

## Common Exam Traps

- Importing a resource ARN does not authorize its use.
- Cross-stack references are not cross-account or cross-Region.
- Producer and consumer are independent stacks but are lifecycle-coupled by the import.

## Memory Hooks

> **Export shares a value; policy grants its use.**

## Quick Review

- Export in the producer and import in the consumer.
- Stay within one account and Region.
- Names must be unique.
- Remove imports before deleting an export.
- Never export secrets.

## Self-Check Questions

1. Why might deletion of a network stack fail?

<details><summary>Answer</summary>

Another stack may still import one of its exported values.

</details>

2. What is the scope of a CloudFormation export?

<details>
<summary>Answer</summary>

Exports are available for import only within the same account and Region.

</details>

3. Why can tight cross-stack references increase operational coupling?

<details>
<summary>Answer</summary>

Consumers block changes or deletion of the producer's export. Use nested stacks, Systems Manager parameters, or another discovery pattern when independent lifecycle is more important.

</details>

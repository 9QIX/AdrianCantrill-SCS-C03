# CloudFormation Mappings

## Overview

The CloudFormation `Mappings` section stores static lookup tables in a template. `Fn::FindInMap` selects a value using top-level and second-level keys, commonly for controlled environment or Region differences.

## Core Concepts

- Mapping keys and values are declared in the template and are not changed by stack operators at deployment.
- Mappings are suitable for finite, stable lookup data—not frequently changing external state or secrets.
- `Fn::FindInMap` needs the mapping name plus two keys.
- Pseudo parameters or input parameters commonly select a mapping branch.

## Security Implications

- A mapping can standardize approved identifiers or settings across environments.
- Stale identifiers can cause deployment failure or insecure fallback choices.
- Templates are not secret stores; mapping values can be inspected.
- Prefer current external mechanisms when values must update independently of the template lifecycle.

## Common Exam Traps

- A mapping is not a parameter and cannot be entered by the stack operator.
- Mapping changes require a template update.
- A missing key fails resolution; there is no implicit wildcard fallback.

## Memory Hooks

> **Mappings are static tables; FindInMap is the lookup.**

## Quick Review

- Use mappings for stable finite choices.
- Select keys with parameters or pseudo parameters.
- Never place secrets in mappings.
- Keep Region-specific values current.
- Validate every key path.

## Self-Check Questions

1. Should a rotating password be stored in a mapping?

<details><summary>Answer</summary>

No. Mappings are visible static template data, not secret storage.

</details>

2. When should a mapping be used instead of a parameter?

<details>
<summary>Answer</summary>

Use a mapping for template-owned lookup data selected from known keys, such as a Region-to-value table. Use a parameter when the deployer should supply the value.

</details>

3. What happens when `Fn::FindInMap` uses a missing key?

<details>
<summary>Answer</summary>

Template processing fails. Validate both map levels and provide mappings for every supported deployment case.

</details>

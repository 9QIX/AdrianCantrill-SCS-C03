# CloudFormation DeletionPolicy and Data Retention

## Overview

The CloudFormation `DeletionPolicy` attribute controls what happens to a resource when its stack is deleted or when the resource is removed from a template. It is a lifecycle safeguard, not a complete backup or disaster-recovery strategy.

## Exam Alignment

- **Primary SCS-C03 Domain:** Data Protection
- **Secondary Domain(s):** Security Foundations and Governance
- **Main AWS Services:** AWS CloudFormation, Amazon S3, Amazon RDS
- **Lesson Type:** Concept
- **Exam Importance:** Medium
- **Core Skill:** Prevent unintended deletion of stateful resources during infrastructure lifecycle operations.

## Core Concepts

- `Delete` removes the physical resource when CloudFormation removes it; this is the typical default.
- `Retain` leaves the physical resource in place but removes it from stack management.
- `Snapshot` creates a final snapshot before deletion for supported resource types.
- `RetainExceptOnCreate` can retain during later operations while allowing cleanup after a failed initial creation.
- `UpdateReplacePolicy` separately controls the old physical resource when an update causes replacement.

## Security Implications

- Retained resources continue to incur charges and require access control, monitoring, inventory, and eventual disposal.
- A snapshot must still be encrypted, access-controlled, retained, and tested for restore.
- A deletion policy does not protect against every service-level deletion, data mutation, account compromise, or Region failure.

## Common Exam Traps

- `DeletionPolicy` and `UpdateReplacePolicy` cover different lifecycle paths.
- `Retain` does not keep the resource in the stack.
- `Snapshot` is supported only by certain resource types.
- Retention is not a substitute for AWS Backup or a tested recovery plan.

## Memory Hooks

> **DeletionPolicy handles removal; UpdateReplacePolicy handles replacement; backup handles recovery.**

## Quick Review

- Protect stateful resources deliberately.
- Distinguish stack deletion from replacement.
- Secure retained resources and snapshots.
- Track orphaned resources after `Retain`.
- Test restoration independently.

## Self-Check Questions

1. What happens after a resource with `Retain` is removed from its stack?

<details><summary>Answer</summary>

The physical resource remains, but CloudFormation no longer manages it as part of that stack.

</details>

2. How do `Retain`, `Snapshot`, and `Delete` differ?

<details>
<summary>Answer</summary>

`Retain` leaves the physical resource, `Snapshot` creates a final snapshot for supported resources before deletion, and `Delete` removes the resource according to service behavior.

</details>

3. Does a deletion policy protect against every deletion path?

<details>
<summary>Answer</summary>

No. It controls CloudFormation actions on the stack resource; direct service deletion, data lifecycle policies, key loss, or application actions require separate controls.

</details>

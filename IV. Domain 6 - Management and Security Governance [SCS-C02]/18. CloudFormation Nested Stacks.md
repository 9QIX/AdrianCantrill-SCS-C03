# CloudFormation Nested Stacks

## Overview

Nested stacks let a parent CloudFormation stack create reusable child stacks through `AWS::CloudFormation::Stack`. They modularize infrastructure but create a parent-controlled lifecycle and require secure template storage and controlled update processes.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** AWS CloudFormation, Amazon S3, IAM
- **Lesson Type:** Architecture
- **Exam Importance:** Medium
- **Core Skill:** Use nested stacks for reusable modules while controlling template provenance, permissions, and lifecycle.

## Core Concepts

- The parent passes parameters to a child and can read child outputs.
- Child templates are typically referenced through a template URL; access, integrity, and versioning of that artifact matter.
- Update and delete operations flow through the parent-child hierarchy.
- A failed child operation can cause parent rollback according to stack behavior.
- Nested stacks differ from StackSets, which deploy stacks across accounts and Regions.

## Security Implications

- Pin reviewed template versions rather than relying on mutable untrusted artifacts.
- Restrict write access to the template bucket and record changes.
- Review IAM resources and capabilities across every nested template.
- Avoid independent changes to children managed by a parent.

## Exam Decision Guide

| Requirement | Choice | Why |
| --- | --- | --- |
| Reusable component inside one stack hierarchy | Nested stack | Parent controls child lifecycle |
| Deploy a baseline across accounts/Regions | CloudFormation StackSets | Targets multiple account/Region instances |
| Share a value between independent stacks | Export/import | Couples only the value, not full lifecycle |

## Common Exam Traps

- Nested stacks are not cross-account deployment by themselves.
- A child stack is not operationally independent of its parent.
- Modularity does not automatically provide least privilege.

## Memory Hooks

> **Nested stacks compose one hierarchy; StackSets distribute across accounts and Regions.**

## Quick Review

- Pass inputs down and outputs up.
- Secure and version child templates.
- Update nested resources through the parent.
- Expect rollback propagation.
- Use StackSets for multi-account/Region rollout.

## Self-Check Questions

1. Which feature best deploys a security baseline to many accounts and Regions?

<details><summary>Answer</summary>

CloudFormation StackSets, not nested stacks alone.

</details>

2. What security boundary do nested stacks not create?

<details>
<summary>Answer</summary>

A nested stack improves template composition but does not create an account, Region, IAM, or blast-radius boundary. The parent controls the nested lifecycle.

</details>

3. How should a nested template be supplied securely?

<details>
<summary>Answer</summary>

Store it in a controlled location, restrict write access, review changes, and pin the intended artifact so an attacker cannot substitute infrastructure code.

</details>

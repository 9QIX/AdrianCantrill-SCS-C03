# CloudFormation Outputs and Exports

## Overview

The CloudFormation `Outputs` section publishes selected stack values after deployment. Outputs can support operators, automation, nested stacks, and cross-stack references, but they must not expose secrets.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** AWS CloudFormation
- **Lesson Type:** Concept
- **Exam Importance:** Supporting
- **Core Skill:** Publish non-sensitive stack values and manage cross-stack exports safely.

## Core Concepts

- Each output has a logical name and a value; description, condition, and export name are optional.
- Outputs appear after a successful stack operation and can be read through APIs and the console.
- An exported output can be imported by another stack in the same account and Region.
- Export names must be unique within an account and Region.
- An export cannot be deleted or changed incompatibly while another stack imports it.

## Security Implications

- Do not output passwords, tokens, private keys, or dynamic secret values.
- Treat resource ARNs and endpoints according to their sensitivity and audience.
- Cross-stack exports create lifecycle coupling; protect shared security resources from accidental deletion.

## Common Exam Traps

- `NoEcho` on a parameter does not safely mask a value copied into `Outputs`.
- Exports are not cross-Region or cross-account references.
- Outputs do not create resources or grant access.

## Memory Hooks

> **Outputs publish; exports share within an account and Region; neither should reveal secrets.**

## Quick Review

- Output only necessary non-sensitive values.
- Export names must be unique.
- Imports create update and deletion constraints.
- Use conditions for environment-specific outputs.
- Outputs grant no permissions.

## Self-Check Questions

1. Can one Region directly import another Region's stack export?

<details><summary>Answer</summary>

No. CloudFormation export/import relationships are scoped to an account and Region.

</details>

2. Why export a CloudFormation output?

<details>
<summary>Answer</summary>

An export lets another stack in the same account and Region import a stable value, reducing duplicated identifiers and manual wiring.

</details>

3. Why can an exported stack value block updates or deletion?

<details>
<summary>Answer</summary>

CloudFormation prevents changing or deleting an export while another stack imports it. Remove or replace dependent imports first.

</details>

# AWS Config: Resource Configuration and Compliance

## Overview

AWS Config records supported resource configurations and relationships and evaluates them against rules. It answers how a resource is or was configured; AWS CloudTrail answers which API activity occurred.

## Exam Alignment

- **Primary SCS-C03 Domain:** Detection
- **Secondary Domain(s):** Security Foundations and Governance
- **Main AWS Services:** AWS Config, AWS CloudTrail, Amazon EventBridge, AWS Systems Manager
- **Lesson Type:** Concept
- **Exam Importance:** High
- **Core Skill:** Use configuration history and rules to detect, investigate, and remediate noncompliant resource state.

## Core Concepts

- The configuration recorder tracks supported resource types in an account and Region.
- A delivery channel sends configuration snapshots and history to Amazon S3 and notifications as configured.
- AWS Config rules evaluate desired state using AWS-managed or custom logic.
- Conformance packs group rules and remediation actions into deployable compliance frameworks.
- Aggregators centralize configuration and compliance views across accounts and Regions; they do not themselves enable recording in source accounts.

## Detection, Logging, and Evidence

Configuration items show resource attributes, relationships, and change history. CloudTrail events help attribute a change to a principal and API call. EventBridge can route compliance state changes, while Systems Manager Automation can remediate supported findings.

## Exam Decision Guide

| Question | Service | Why |
| --- | --- | --- |
| What was this resource configured like yesterday? | AWS Config | Maintains configuration history for recorded resources |
| Who changed the security group? | AWS CloudTrail | Records API activity and caller context |
| Is the configuration compliant with a rule? | AWS Config rule | Evaluates resource state |
| Trigger remediation from a compliance change | EventBridge plus automation | Routes and performs the response |

## Troubleshooting

| Symptom | Likely Cause | Verification | Resolution |
| --- | --- | --- | --- |
| No resource history | Recorder disabled or type/Region excluded | Inspect recorder scope and status | Enable correct recording scope |
| Aggregator lacks account data | Source authorization or recording missing | Check aggregation authorization and source recorder | Fix both source and aggregator configuration |
| Noncompliance persists | Remediation absent or failing | Inspect rule and automation execution | Correct permissions, parameters, or resource state |

## Common Exam Traps

- AWS Config is not an API audit log.
- Recording does not equal compliance evaluation.
- Aggregation does not enable source recording.
- Detection is not prevention; remediation must be configured separately.

## Memory Hooks

> **CloudTrail records actions; Config records resource state and evaluates it.**

## Quick Review

- Enable recording in every required account and Region.
- Use rules for state evaluation.
- Use aggregators for centralized visibility.
- Correlate Config history with CloudTrail attribution.
- Automate remediation only with controlled permissions and testing.

## Self-Check Questions

1. Which service shows who changed a resource?

<details><summary>Answer</summary>

AWS CloudTrail. AWS Config shows configuration state and history, not complete API attribution.

</details>

2. Which service answers who changed a resource rather than how it was configured?

<details>
<summary>Answer</summary>

AWS CloudTrail records supported API activity and caller context. AWS Config records supported resource configuration and compliance over time.

</details>

3. Why can an AWS Config rule show no evaluation?

<details>
<summary>Answer</summary>

The recorder, delivery channel, resource type, Region, rule scope, or required permissions may be missing. Verify each dependency and the rule's evaluation status.

</details>

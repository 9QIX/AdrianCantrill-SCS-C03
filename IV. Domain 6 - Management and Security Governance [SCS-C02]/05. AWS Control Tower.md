# AWS Control Tower Governance

## Overview

AWS Control Tower establishes and governs a multi-account landing zone using AWS Organizations and other AWS services. It provides account provisioning, centralized governance, and controls while leaving workload permissions and security operations as separate responsibilities.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Detection
- **Main AWS Services:** AWS Control Tower, AWS Organizations, AWS Config, AWS CloudTrail, AWS IAM Identity Center
- **Lesson Type:** Architecture
- **Exam Importance:** High
- **Core Skill:** Select Control Tower for governed multi-account setup and distinguish preventive, detective, and proactive controls.

## Core Concepts

- A landing zone is the governed multi-account environment, including organization structure, shared accounts, identity, and controls.
- Account Factory standardizes account provisioning.
- Controls express governance objectives. Depending on implementation, they can prevent actions, detect noncompliance, or evaluate resources before provisioning.
- Control Tower orchestrates underlying services; it does not replace Organizations, IAM, Config, or CloudTrail.
- Drift occurs when governed resources are changed outside supported Control Tower workflows.

## Architecture and Service Relationships

```text
AWS Control Tower
  |-- AWS Organizations: accounts, OUs, policies
  |-- IAM Identity Center: workforce access
  |-- CloudTrail: activity evidence
  |-- AWS Config: configuration recording/evaluation
  `-- Account Factory: standardized provisioning
```

## Exam Decision Guide

| Requirement or Clue | Service or Control | Why |
| --- | --- | --- |
| Governed landing zone with least setup effort | AWS Control Tower | Orchestrates prescriptive multi-account governance |
| Custom account hierarchy and policies only | AWS Organizations | Core organization capability without landing-zone orchestration |
| Block prohibited API actions | Preventive control/SCP | Restricts authorization before the action succeeds |
| Report configuration noncompliance | Detective control/AWS Config | Evaluates state and reports drift |

## Common Exam Traps

- Detective controls report; they do not necessarily prevent resource creation.
- Control Tower does not make every workload compliant automatically.
- The management account remains highly privileged and should not host ordinary workloads.
- Direct changes to managed resources can create drift.

## Memory Hooks

> **Organizations is the foundation; Control Tower is the governed landing-zone orchestrator.**

## Quick Review

- Use Control Tower for prescriptive multi-account governance.
- Account Factory standardizes account creation.
- Understand preventive, detective, and proactive control behavior.
- Underlying services still perform enforcement and recording.
- Monitor and repair drift.

## Self-Check Questions

1. Which service should be chosen for a prescriptive governed landing zone with standardized account vending?

<details><summary>Answer</summary>

AWS Control Tower, with Account Factory for standardized provisioning.

</details>

2. How does AWS Control Tower relate to AWS Organizations?

<details>
<summary>Answer</summary>

Control Tower establishes and governs a landing zone using Organizations and integrated services. Organizations supplies the account hierarchy and SCP foundation; Control Tower adds orchestration, controls, and drift governance.

</details>

3. What should be checked when an enrolled account is noncompliant?

<details>
<summary>Answer</summary>

Identify the failed control and resource, inspect AWS Config and CloudTrail evidence, remediate the resource, and check for landing-zone or account drift rather than assuming the control grants permission.

</details>

# Animals4life Security Scenario

## Overview

Animals4life is a fictitious organization used to connect AWS security controls to realistic business requirements. Treat each later design as a risk decision: identify assets and actors, define trust boundaries, select controls, collect evidence, and plan recovery.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Incident Response
- **Main AWS Services:** AWS Organizations, AWS Identity and Access Management (IAM), AWS CloudTrail, AWS Config
- **Lesson Type:** Architecture
- **Exam Importance:** Supporting
- **Core Skill:** Translate business security requirements into layered AWS controls.

## Core Concepts

- Separate production, security, logging, and other workloads when isolation or ownership demands it.
- Apply least privilege to workforce identities, workloads, and cross-account access.
- Classify data before choosing encryption, retention, access, and monitoring controls.
- Preserve logs in a controlled location so investigation does not depend on the compromised workload account.
- Define owners, escalation paths, containment actions, and recovery requirements before an incident.

## How It Works

```text
Business requirements -> Threats and data classification -> Preventive controls
                                                |-> Detective controls
                                                |-> Response and recovery plan
```

## Exam Decision Guide

| Requirement or Clue | Most Likely Control | Why |
| --- | --- | --- |
| Maximum permissions across member accounts | Service control policy (SCP) | Establishes an organization guardrail without granting permissions |
| Record account API activity | AWS CloudTrail | Provides API and sign-in event evidence |
| Evaluate configuration over time | AWS Config | Records supported resource configuration and evaluates rules |
| Central workforce access | AWS IAM Identity Center | Provides centrally managed access to multiple AWS accounts |

## Common Exam Traps

- A compliance requirement is not satisfied by a single service; evidence, enforcement, ownership, and remediation may all be required.
- Centralized logging records evidence but does not itself prevent compromise.
- Multi-account isolation reduces blast radius but does not replace least privilege inside each account.

## Memory Hooks

### Mental Model

Treat the organization as a building: accounts are fire compartments, IAM controls keys, guardrails limit what rooms can contain, and logs are the security-camera archive.

## Quick Review

- Start with assets, actors, threats, and requirements.
- Use layered preventive, detective, and responsive controls.
- Centralize governance and evidence where appropriate.
- Design for failure and recovery.
- Validate every control against the intended risk.

## Self-Check Questions

1. What should precede selecting an AWS security service?

<details><summary>Answer</summary>

Identify the business requirement, protected asset, actors, threat, and trust boundary.

</details>

2. Why centralize security logs?

<details><summary>Answer</summary>

It improves organization-wide visibility and helps preserve evidence outside a potentially compromised workload account.

</details>

# Networking and Technical Fundamentals Prerequisites

## Overview

SCS-C03 security scenarios assume working knowledge of networking, Domain Name System (DNS), encryption, and common protocols. The detailed foundation material has moved to a separate course, but these concepts remain prerequisites for evaluating trust boundaries and diagnosing failures.

## Exam Alignment

- **Primary SCS-C03 Domain:** Infrastructure Security
- **Secondary Domain(s):** Data Protection
- **Main AWS Services:** Amazon VPC, Amazon Route 53, AWS Key Management Service (AWS KMS)
- **Lesson Type:** Text-Based Reference
- **Exam Importance:** Supporting
- **Core Skill:** Identify foundational knowledge needed for secure AWS architecture and troubleshooting.

## Required Foundations

- IPv4 addressing, Classless Inter-Domain Routing (CIDR), routing, ports, and stateful versus stateless filtering.
- DNS resolution, hosted zones, record types, delegation, DNSSEC, and resolver paths.
- Symmetric and asymmetric cryptography, hashing, signing, certificates, and Transport Layer Security (TLS).
- Public-key infrastructure, certificate trust, encryption at rest, and encryption in transit.
- Authentication, authorization, least privilege, and defense in depth.

## Exam Decision Guide

| Requirement or Clue | Foundation to Apply | Why |
| --- | --- | --- |
| Connection timeout | Routing and network filtering | The path or return path may be blocked |
| Certificate warning | PKI, names, trust chain, and validity | TLS identity validation is failing |
| Private name does not resolve | DNS resolver and hosted-zone association | Name resolution precedes connection establishment |
| Ciphertext confidentiality and controlled key use | Encryption and key authorization | Data encryption and key access are distinct decisions |

## Common Exam Traps

- A security group is stateful; a network ACL is stateless.
- DNS resolution success does not prove network reachability.
- TLS provides in-transit protection; it does not establish authorization to an AWS resource.
- Encryption at rest does not prevent an authorized principal from reading decrypted data.

## Memory Hooks

### Decision Memory Hook

> **Resolve the name, route the packet, permit the flow, authenticate the peer, then authorize the action.**

## Quick Review

- Know packet paths and return paths.
- Separate DNS, connectivity, TLS, authentication, and authorization failures.
- Understand basic cryptographic purposes and limits.
- Treat these fundamentals as prerequisites, not optional exam trivia.
- Use labs to close weak areas.

## Self-Check Questions

1. Why can DNS succeed while an application connection fails?

<details><summary>Answer</summary>

DNS only resolves a name. Routing, filtering, TLS, and application authorization can fail afterward.

</details>

2. Does encryption at rest deny an authorized application access to plaintext?

<details><summary>Answer</summary>

No. An authorized service or principal can receive decrypted data; access control and key authorization must also be designed correctly.

</details>

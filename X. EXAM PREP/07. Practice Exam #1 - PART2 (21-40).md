# Practice Review 2: Federation, Private Connectivity, and Edge Security

## Overview

The second practice set connects identity federation, KMS authorization, end-to-end TLS, private AWS connectivity, cross-account roles, network filtering, Amazon Cognito, private CloudFront content, AWS Direct Connect, and AWS Certificate Manager (ACM). This reference captures the decision skills without duplicating the quiz questions.

## Exam Alignment

- **Primary SCS-C03 Domain:** Identity and Access Management
- **Secondary Domain(s):** Infrastructure Security, Data Protection
- **Main AWS Services:** AWS IAM, AWS KMS, AWS PrivateLink, Amazon VPC, AWS Direct Connect, Amazon Cognito, Amazon CloudFront, AWS Certificate Manager
- **Lesson Type:** Text-Based Reference
- **Exam Importance:** High
- **Core Skill:** Combine identity, network-path, certificate, and encryption requirements without confusing their scopes.

## Knowledge Connectors

- IAM is global, but policies often contain Region-specific resource ARNs, conditions, keys, or dependencies. A Region move can therefore break authorization even though IAM itself is not regional.
- Reading a Systems Manager Parameter Store `SecureString` requires both Parameter Store access and permission to decrypt with the applicable KMS key.
- An Application Load Balancer can terminate TLS and establish a separate HTTPS connection to targets; a Network Load Balancer TCP listener can pass encrypted traffic through.
- CloudFront origin access control (OAC) plus an S3 bucket policy can restrict S3 access to the intended distribution. Signed URLs or signed cookies control viewer access and do not, alone, secure the origin.
- IAM policy variables can scope S3 prefixes to federated identity attributes.
- For private paths, use appropriate VPC endpoints for AWS services and a VPN or Direct Connect design for on-premises connectivity. Direct Connect is not encrypted by default.
- Cross-account workforce or auditor access normally uses roles or IAM Identity Center rather than duplicating IAM users.
- Cognito user pools handle application sign-up/sign-in; identity pools exchange supported identities for temporary AWS credentials and can support unauthenticated identities.
- CloudFront ACM certificates must be in `us-east-1`; certificates attached to regional load balancers must be in the load balancer's Region.

## Exam Decision Guide

| Requirement | Likely Choice | Why |
| --- | --- | --- |
| Human access across an organization | IAM Identity Center | Central workforce access and permission sets. |
| Customer application identities | Cognito user pool | Managed sign-up, sign-in, and federation. |
| Temporary AWS permissions for app identities | Cognito identity pool or direct STS pattern | Exchanges an identity for temporary credentials. |
| Private S3/DynamoDB access from a VPC | Gateway endpoint | Keeps supported service traffic off the public internet. |
| Private access to many other AWS services | Interface endpoint | AWS PrivateLink-powered elastic network interfaces. |
| Private CloudFront-to-S3 origin | OAC and restrictive bucket policy | Prevents bypass of viewer authorization. |

## Common Exam Traps

- A private network path does not automatically provide encryption in transit.
- IAM permission to read a `SecureString` is insufficient if KMS denies decryption.
- Signed URLs protect viewer access, not the S3 origin by themselves.
- Direct Connect provides dedicated connectivity, not native encryption.
- Cognito is for application customers; IAM Identity Center is for workforce access.

## Memory Hooks

> **Identity decides who, endpoints decide the path, TLS protects the hop, and KMS controls key use.**

## Quick Review

- Recheck Region-specific ARNs and conditions during migrations.
- Evaluate both service and KMS permissions for encrypted values.
- Secure both CloudFront viewer access and origin access.
- Use roles for cross-account access.
- Separate user-pool authentication from identity-pool AWS credentials.
- Place ACM certificates in the Region required by the consuming service.

## Self-Check Questions

1. Why can reading a `SecureString` fail despite `ssm:GetParameter` permission?

<details><summary>Answer</summary>

The principal can still lack `kms:Decrypt`, or the KMS key policy or another guardrail can deny it.

</details>

2. Does Direct Connect encrypt traffic automatically?

<details><summary>Answer</summary>

No. Add an encryption mechanism such as IPsec or MAC Security where supported and required.

</details>

3. Where must an ACM certificate for CloudFront be provisioned?

<details><summary>Answer</summary>

US East (N. Virginia), `us-east-1`.

</details>

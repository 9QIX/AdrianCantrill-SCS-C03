# Practice Review 1: Cross-Account Access, Network Controls, and Encryption

## Overview

This first practice set is a diagnostic covering cross-account access, distributed denial-of-service (DDoS) protection, VPC traffic inspection, security groups and network ACLs, AWS Key Management Service (AWS KMS), load-balancer security, Systems Manager access, and IAM policy evaluation. The questions themselves remain in the course quiz; this chapter records the reasoning objectives without reproducing them.

## Exam Alignment

- **Primary SCS-C03 Domain:** Infrastructure Security
- **Secondary Domain(s):** Identity and Access Management, Data Protection, Security Foundations and Governance
- **Main AWS Services:** IAM Identity Center, AWS STS, AWS Shield Advanced, VPC Traffic Mirroring, Amazon VPC, AWS KMS, Amazon S3, AWS CloudTrail, AWS Systems Manager
- **Lesson Type:** Text-Based Reference
- **Exam Importance:** High
- **Core Skill:** Translate a security requirement into the AWS control whose scope and behavior satisfy every constraint.

## Knowledge Connectors

- Workforce access across multiple accounts generally points to IAM Identity Center; application-level temporary credentials and direct role assumption point to AWS Security Token Service (AWS STS).
- Shield Advanced adds enhanced DDoS protections, the AWS Shield Response Team, and eligible cost-protection benefits; Shield Standard is automatic baseline protection.
- VPC Flow Logs provide network metadata, not packet payloads. Traffic Mirroring supplies packet copies for inspection appliances.
- Security groups are stateful and can reference another security group. Network ACLs are stateless, subnet-scoped, and evaluate numbered rules from lowest upward.
- AWS KMS key deletion uses a waiting period; imported key material can be deleted and reimported, subject to matching material and metadata requirements.
- SSE-KMS supports separation between S3 data permissions and KMS key-use permissions. SSE-C and client-side encryption use different key-custody models.
- Service control policies (SCPs) do not restrict the organization management account.
- Systems Manager Session Manager supports private administrative access when the required Systems Manager connectivity and IAM permissions exist.
- IAM starts with implicit deny; an applicable allow is required, and an applicable explicit deny overrides an allow.

## Exam Decision Guide

| Clue | Likely Control | Deciding Detail |
| --- | --- | --- |
| Inspect packet contents | VPC Traffic Mirroring plus inspection targets | Flow Logs contain metadata only. |
| Block a known source range at subnet boundary | Network ACL deny rule | Security groups do not support explicit deny. |
| Organization trail encrypted under customer control | Customer-managed KMS key with appropriate policy | AWS-managed keys cannot be edited for the needed cross-account policy design. |
| TLS cipher weakness on an ALB | Update its security policy | The security policy controls supported protocols and ciphers. |
| API authorization outcome | Evaluate all applicable policies and guardrails | Explicit deny wins over allow. |

## Common Exam Traps

- Detection and prevention are not interchangeable.
- A managed service name does not override a hard custody, Region, or account-boundary requirement.
- NACL response traffic needs its own matching rule.
- IAM policies do not control Linux file permissions.

## Memory Hooks

> **Match scope first: identity, resource, subnet, packet, key, account, or organization.**

## Quick Review

- Identify the requested outcome before comparing products.
- Distinguish packet payloads from flow metadata.
- Distinguish stateful security groups from stateless NACLs.
- Check who owns and can use encryption keys.
- Separate DDoS protection from threat detection.
- Apply the complete IAM evaluation model.

## Self-Check Questions

1. Which feature provides packet copies for deep inspection?

<details><summary>Answer</summary>

VPC Traffic Mirroring, together with an appropriate inspection target.

</details>

2. Why can a security group not block one hostile IP with an explicit-deny rule?

<details><summary>Answer</summary>

Security groups contain allow rules only; a network ACL or an application-edge control such as AWS WAF may provide the required deny capability, depending on scope.

</details>

3. What wins when an applicable allow and explicit deny conflict?

<details><summary>Answer</summary>

The explicit deny.

</details>

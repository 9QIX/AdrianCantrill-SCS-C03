# AWS Question Analysis Technique — Part 2

## Overview

Part 2 applies constraint matching to a multiple-response encryption scenario. The central lesson is that every selected answer must satisfy every mandatory requirement; partial matches are distractors.

## Exam Alignment

- **Primary SCS-C03 Domain:** Data Protection
- **Secondary Domain(s):** Security Foundations and Governance
- **Main AWS Services:** Amazon S3, AWS Key Management Service (AWS KMS)
- **Lesson Type:** Policy Analysis
- **Exam Importance:** Medium
- **Core Skill:** Select encryption controls by matching key custody, encryption location, and data-protection requirements.

## Constraint-Matching Workflow

1. Convert the question into atomic requirements.
2. Create a mental pass/fail test for each requirement.
3. Evaluate every option against all tests.
4. For multiple-response questions, verify that each selected option is independently valid unless the wording explicitly asks for components of one combined solution.

## Encryption Example

The source requires data encrypted at rest while encryption keys remain on premises. The key distinction is not merely “server-side” versus “client-side”; it is who supplies and retains the key material.

| Method | Where encryption occurs | Key custody relevant to the scenario | Fits an on-premises-key requirement? |
| --- | --- | --- | --- |
| SSE-S3 | Amazon S3 | AWS manages the keys | No |
| SSE-KMS | Amazon S3 | AWS KMS protects the KMS key | No, if the requirement literally says the encryption key must remain on premises |
| SSE-C | Amazon S3 | Customer supplies the key with each request; S3 does not store the key | Potentially, subject to the exact custody and operational requirements |
| Client-side encryption | Before upload | Customer controls the client-side key and process | Yes, when designed so plaintext keys remain on premises |

SSE-C requires HTTPS. The client must provide the key for retrieval, and losing it makes the object unrecoverable. AWS recommends carefully assessing its operational burden against client-side encryption or AWS KMS designs.

## Common Exam Traps

- Encryption at rest does not establish who controls or stores the key.
- An AWS KMS key with imported material is still operated within AWS KMS; importing material does not mean the usable key remains exclusively on premises.
- “AWS never sees plaintext” points toward client-side encryption, not server-side encryption.
- Do not select an option solely because it contains a security-related service name.

## Memory Hooks

### Decision Memory Hook

> **Ask three questions: Who encrypts? Who supplies the key? Where can the key exist?**

## Quick Review

- Break compound requirements into separate pass/fail checks.
- All selected answers must satisfy all mandatory constraints.
- SSE-S3 and SSE-KMS use AWS-side key handling.
- SSE-C uses a customer-provided key per request.
- Client-side encryption protects data before it reaches Amazon S3.
- Key custody and encryption location are different design decisions.

## Self-Check Questions

1. Why does SSE-KMS not meet a requirement that the operative encryption key remain exclusively on premises?

<details><summary>Answer</summary>

AWS KMS performs cryptographic operations using key material protected within the KMS service boundary.

</details>

2. Which approach ensures Amazon S3 receives ciphertext rather than plaintext?

<details><summary>Answer</summary>

Client-side encryption.

</details>

3. What must be tested before selecting an answer in a multiple-response question?

<details><summary>Answer</summary>

Confirm that it satisfies every mandatory requirement and that the required number of selections is correct.

</details>

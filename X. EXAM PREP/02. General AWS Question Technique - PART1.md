# AWS Question Analysis Technique — Part 1

## Overview

This lesson develops a repeatable way to reduce a long scenario into technical requirements, eliminate impossible options, and select the answer that satisfies the stated constraint. Part 1 applies the method to an Application Load Balancer (ALB) scenario.

## Exam Alignment

- **Primary SCS-C03 Domain:** Security Foundations and Governance
- **Secondary Domain(s):** Infrastructure Security
- **Main AWS Services:** Elastic Load Balancing, Amazon EC2 Auto Scaling
- **Lesson Type:** Policy Analysis
- **Exam Importance:** Supporting
- **Core Skill:** Separate scenario context from decision-driving requirements and evaluate each answer against AWS service capabilities.

## Question-Decomposition Method

1. Identify whether the item is single-choice or multiple-response and note how many answers are required.
2. Scan the answers for impossible service behavior or nonexistent features.
3. Extract constraints from the scenario: security, cost, performance, deployment time, operational effort, availability, account boundary, or Region.
4. Identify important omissions. A service that is not present cannot perform an action attributed to it.
5. Remove wording shared by every option and compare the technical differences.
6. Eliminate answers that violate any hard requirement.
7. Validate the remaining answer end-to-end rather than selecting it only because the others appear weak.

## Worked Architecture Reasoning

The source scenario places multiple Amazon Elastic Compute Cloud (Amazon EC2) instances behind an ALB but does not include an Auto Scaling group.

```text
Client
  |
  v
Application Load Balancer
  | health checks and request routing
  +------> Healthy EC2 target
  +--X---> Failed or unhealthy target
```

The ALB can use health checks to stop routing requests to an unhealthy target. It does not, by itself, terminate or replace the EC2 instance; replacement requires a separate capacity-management mechanism such as EC2 Auto Scaling. One failed target also does not imply that the load balancer must return an error while other healthy targets can serve the request.

## Exam Decision Guide

| Requirement or Clue | Most Likely Interpretation | Why |
| --- | --- | --- |
| Stop routing to an unhealthy registered target | Load balancer health checks | The load balancer controls target selection. |
| Replace an unhealthy EC2 instance in a fleet | EC2 Auto Scaling health replacement | The Auto Scaling group manages desired capacity. |
| “Most cost-effective” | Compare all technically valid choices by total cost | Cost matters only after requirements are met. |
| Very short implementation window | Exclude solutions with long provisioning lead times | A technically capable option can still violate a hard time constraint. |

## Common Exam Traps

- Do not give one service the capabilities of another; an ALB routes traffic, whereas an Auto Scaling group manages instance count.
- “Best practice” does not mean the most elaborate design. Prefer the supported, least-privilege, operationally appropriate option.
- Missing architecture components can be deliberate clues.
- A cheaper option that fails a security or availability requirement is not cost-effective.

## Memory Hooks

> **Extract constraints, eliminate impossibilities, compare differences, then validate the survivor.**

## Quick Review

- Determine how many answers must be selected.
- Translate prose into hard technical requirements.
- Look for absent components as well as present ones.
- Remove repeated wording from answer comparisons.
- Map each claimed action to the service that actually performs it.
- Validate the final choice against every requirement.

## Self-Check Questions

1. Why can an ALB stop sending requests to a failed target without replacing it?

<details><summary>Answer</summary>

Health checks control routing, but instance replacement is a capacity-management function such as EC2 Auto Scaling.

</details>

2. When should cost be used as the deciding factor?

<details><summary>Answer</summary>

After identifying the options that satisfy all mandatory technical and security requirements.

</details>

3. Why is repeated wording across every answer often low value?

<details><summary>Answer</summary>

It does not distinguish the choices; the technical differences determine which option fits.

</details>

# Exam Walkthrough: TLS Termination and Certificate Separation

## Overview

This walkthrough analyzes how to keep a website certificate and private key away from administrators who have root access to backend Amazon EC2 instances. The architectural answer is to terminate Transport Layer Security (TLS) on an Application Load Balancer (ALB) using AWS Certificate Manager (ACM), so the certificate need not be installed on those instances.

## Exam Alignment

- **Primary SCS-C03 Domain:** Data Protection
- **Secondary Domain(s):** Infrastructure Security, Identity and Access Management
- **Main AWS Services:** AWS Certificate Manager, Elastic Load Balancing, Amazon EC2
- **Lesson Type:** Architecture
- **Exam Importance:** Medium
- **Core Skill:** Place TLS keys outside an administrative trust boundary by terminating TLS on a managed load balancer.

## Architecture and Service Relationships

```text
Client --HTTPS--> ALB with ACM certificate --HTTP or HTTPS--> EC2 targets
                    ^
                    |
             Certificate boundary
```

- ACM deploys a supported certificate to the ALB HTTPS listener.
- The ALB terminates the client TLS connection and forwards requests to its target group.
- If the target protocol is HTTP, no server certificate or private key is required on the EC2 instances.
- If policy requires encryption on the backend hop, use HTTPS to the targets with a separate backend certificate; do not assume the public edge certificate must be copied to each instance.

## Security Reasoning

Root access defeats file permissions inside the instance. Storing a certificate in Amazon S3 temporarily, deleting it after startup, or restricting its local file with POSIX permissions cannot keep it secret from a root administrator. IAM groups also cannot be used as Linux file owners or POSIX permission subjects.

Using an ACM certificate on an ALB separates certificate administration from instance administration and reduces private-key distribution. Access to ACM and load-balancer configuration should be controlled with IAM permissions and logged through AWS CloudTrail.

## Exam Decision Guide

| Requirement or Clue | Most Likely Control | Why |
| --- | --- | --- |
| TLS for an ALB without placing the key on EC2 | ACM certificate on an HTTPS listener | ALB terminates TLS using the integrated certificate. |
| End-to-end encryption to targets | HTTPS target group with an appropriate backend certificate | The backend hop is encrypted separately. |
| Prevent a root user from reading a local private key | Do not place that key on the instance | Root can bypass local file controls. |

## Common Exam Traps

- TLS offload protects the client-to-ALB hop; HTTP to targets is not end-to-end encryption.
- Root users cannot be constrained by ordinary local file permissions.
- IAM authorization and Linux POSIX authorization are different systems.
- ACM now supports exportable public certificates, but exporting a private key to EC2 reintroduces the custody problem.

## Memory Hooks

> **If instance root must not hold the key, terminate TLS before the instance.**

## Quick Review

- Put the ACM certificate on the ALB HTTPS listener.
- HTTP targets avoid installing the public certificate key on EC2.
- Use HTTPS targets when backend-hop encryption is required.
- Root access defeats instance-local certificate hiding.
- Separate certificate-management permissions from instance-management permissions.

## Self-Check Questions

1. Why does deleting a certificate after instance startup not protect it from a root administrator?

<details><summary>Answer</summary>

The administrator can change the startup process, intercept the certificate, inspect process memory, or alter local controls.

</details>

2. What does an ALB HTTPS listener do?

<details><summary>Answer</summary>

It negotiates and terminates the client TLS connection using a configured server certificate, then forwards the request to a target.

</details>

3. Does TLS offload provide end-to-end encryption?

<details><summary>Answer</summary>

Not when the ALB-to-target protocol is HTTP. Configure HTTPS targets when the backend hop must also be encrypted.

</details>
